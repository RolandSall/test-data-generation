# Feedback implementation review

This review records the original support, executable limitations, delivered change, compatibility and regression coverage for each request. The library changes stay independent of applications, databases and runners; optional runner compatibility is exercised only in consumer checks. User-facing behavior is documented in the linked guides.

1. **Branded primitives.** Ordinary primitives were supported; readonly unique-symbol string/number brands failed as primitive methods were treated as object methods. Extraction now recognizes required readonly unique-symbol literal markers, including nested/collection properties and literal primitives, while retaining the declared generic output type. Arbitrary intersections, string-key brands and extra structural requirements remain explicit errors. Existing extraction is unchanged. Coverage: [typescript-brands.test.ts](../../packages/test-data/test/typescript-brands.test.ts), including compile-time type assertions and rejected intersection patterns. See [model documentation](../models.md#branded-primitives).
2. **Defaults and optionals.** Optional probabilities and preservation of supplied falsy/empty values already worked; Zod/JSON Schema defaults were ignored. The additive `schemaDefaults: 'preserve'` policy preserves declared defaults, defers factories, copies mutable values, and processes Zod prefaults. Generation and populated optionals remain the defaults; field instructions/providers win. Existing optional/fill APIs are documented instead of duplicated. Coverage: [schema-defaults.test.ts](../../packages/test-data/test/schema-defaults.test.ts), including null, false, zero, empty strings/collections, nested defaults, factories, overrides and optional omission. See [configuration](../configuration.md#schema-defaults-and-optional-properties).
3. **Input/output schemas.** Root synchronous transforms worked, but nested transforms were revalidated as raw input; pipeline/refinement errors lost paths. Output remains the default; the additive input mode returns valid raw input with its Zod input type. Output validation does not re-run input transformations; pipeline rejection is bounded and keeps actionable paths/messages. Simple defaulted primitives retain kind rules/providers. Practical format support includes IPv6 and ISO local time. Async effects, arbitrary inverse transforms and unrepresentable preprocess input remain explicit limitations. Coverage: [zod-modes.test.ts](../../packages/test-data/test/zod-modes.test.ts), including nested/root transforms, pipelines, output overrides, formats, refinements, defaults and inferred types. See [Zod models](../models.md#zod).
4. **Selective generation.** Existing omission rules could express selected objects, but blank objects retained empty branches, and field omission left an own undefined key. Full generation remains the default. Per-call `onlyProvided: true` now selects the merged fields tree, supports fixed values/generators, and returns a partial type across single/batch/stream/result/session calls. Blank behavior stays unchanged. Omission removes own keys consistently; this is an observable bug correction. Required-schema checking still rejects incomplete objects. Partial class factories/arbitrary object transforms are rejected unless explicitly replaced by a complete value/generator. Coverage: [only-provided.test.ts](../../packages/test-data/test/only-provided.test.ts), including own-property assertions, nested selection, mode types, unknown properties, null/undefined distinctions, class safety and unchanged normal generation. See [selective generation](../graphs.md#only-provided-properties).
5. **Compatibility/replay.** Peer ranges and basic replay/session documentation existed, but CI checked pinned versions only. A separate minimum/current optional-peer matrix now compiles installed public declarations and runs packed adapter/runner consumers. The [compatibility and replay contract](../compatibility.md) records exact verified versions, configurations, stable replay inputs, uniqueness domains and isolation. Generation algorithms/state ownership are unchanged. Coverage: [replay-contract.test.ts](../../packages/test-data/test/replay-contract.test.ts) and [check-peer-compatibility.ts](../../scripts/check-peer-compatibility.ts); core-only installation remains covered by the existing pack checker.

Defaults, input/output modes, selective generation and replay have runnable [playground scenarios](../../playground/schema-policies/README.md). The README begins with a complete simple usage example before linking to detailed guides.
